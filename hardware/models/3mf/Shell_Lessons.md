### P28｜10/20 当前版：绕过了已有安装孔，孔径记录还存在冲突

**违反 R24。** 当前 README 明写“新增两孔不用作支撑”“不用新增 0.6 mm 孔承重”；`build.py` 第 176 行也写 `no reliance on the new 0.6 mm holes`。PCB 仅靠 X=`[4.0,55.0,132.4]` 的三对板边托位／压指和端挡定位。装配参考板仍是未含新孔的 STEP，外壳没有按两孔中心做配合。

原始差异证据保存的两孔为孔层 `FILL`，其 `path` 是 `CIRCLE`：

| ID | 原始 path | 按当前平移后的孔中心／mm | 中心至板边 |
|---|---|---|---|
| `8a08118428949267` | `['CIRCLE', -5010, -1095, 23.622]` | `(1.143, 15.240)` | 约 1.1 mm |
| `845a3a28dd9fe12d` | `['CIRCLE', 235, -2290, 23.622]` | `(134.366, −15.113)` | 约 1.3 mm |

来源：[live-check-evidence.json](../.pcba-workflow/pcb1_2-recheck-20261018/live-check-evidence.json)。坐标按 mil×0.0254，再加当前脚本平移 `(128.397,43.053)`；板包络为 X=0…135.890、Y≈±16.383 mm。上表边距是孔中心到最近板边的距离。

**孔径推断：**按嘉立创 EDA 专业版 `CIRCLE` 格式，第三个数值参数 `23.622 mil` 是半径，换算约 0.600 mm，因此孔径约 **1.200 mm**。README 的“0.6 mm 孔”把该数当成了孔径。按这个推断，两孔孔边到最近板边约剩 0.5–0.7 mm。

**需要 Hsinlung 在 EDA 确认：实际孔径，以及它是否符合原来的安装意图。** L16，475 行本人早先接受“两端各一个 M2 孔，阵列底下不打孔”，与推算 Ø1.2 mm 对不上。本文记录冲突，保留板和壳原样。

经验没用上的直接证据是：制作时知道新增孔，仍在实现中明确排除它们，没有把孔位、孔径与原固定意图一起核对。

### P29｜10/20 当前版：握持段按充电宝底面定高，多撑厚约 2.47 mm

**违反 R02，重复 P14 的握持收窄问题。** 充电宝已放在板后，但它的底面仍决定了前方握持段的高度。

当前 `build.py` 第 47–52 行的计算是：

```text
FACE = PCB_TOP + MODULE_SEATED_HEIGHT = 2.204 + 24.30 = 26.504
PB_Z = 3.334，PB_THICKNESS = 26.5，PB_CLEAR = 0.65，WALL = 2.4
PB 所需外底面 = 3.334 − 26.5/2 − 0.65 − 2.4 = −12.966
AXIS = (FACE + PB 所需外底面)/2 = 6.769
BOTTOM = 2*AXIS − FACE = −12.966
```

`tube_envelope()` 在握持段、X=105、PB 段和尾端共用 `BOTTOM/FACE`。于是 [verification.json](Handle_NewPCB_2026-10-20/models/verification.json) 报握持段 **39.266×39.470 mm**、尾段 **56.538×39.470 mm**，两段一样高。

回读 `models/pcb_parts.npz` 及索引，板底最低器件是 **C76，底 Z=−7.750 mm**，在当前坐标 X≈82.714…90.514 mm。按同样普通间隙 0.35 mm、壳壁 2.4 mm比较：

```text
握持段本地最低器件所需外底面 = −7.750 − 0.350 − 2.400 = −10.500 mm
当前底面多下探 = −10.500 − (−12.966) = 2.466 mm，约 2.47 mm
```

因此，“握持段尽量窄”没有落实到本段硬件包络：脚本直接让远处充电宝决定了整段底面。Coaxial_v1 已有分段收底，`shape.py` 的 `YBOT` 从电池段 −22.3 收到握持段 −8.79，再到尾部 −15.0；10/20 没沿用这种按段处理。两版坐标轴不同，比较的是分段方法，非照抄旧尺寸。

**能收到多少还要重核同轴、螺柱、按钮和装配约束。** 这不改变当前把充电宝所需高度带到握持段、违反收窄要求的结论。
