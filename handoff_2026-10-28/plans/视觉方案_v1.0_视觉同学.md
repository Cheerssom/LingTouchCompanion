# 灵触：CS30、SpatialLM 与图像补检融合技术方案

版本：v1.0，2026-10-28。用途：供 Claude 审阅架构、指出缺陷和安排下一阶段实现。本文件是拟实施方案，不代表下文功能已全部接通。

## 1. 目标与固定约束

眼镜视角获取环境信息，将真实空间中的障碍投影到地面 xOy，输出触觉装置使用的矩阵，同时展示墙、门窗和物体的语义结构。

- 9 列 × 6 行，每格 0.4 m；横向 x∈[-1.8,1.8)，前向覆盖 y=0～2.4 m。保持现有范围，不改为1～3.4 m，也不拉伸成扇形。
- x 向相机右侧、y 向相机前方在地面的投影方向、z 向上。原点为相机垂直投影到地面的位置；相机并不严格处于人体中心，该偏移暂不补偿。
- 当前采用跟随头部朝向的地图。身体朝向地图不是本版目标。
- 用(x,y)确定格子，z只用于高度筛选；同一空间位置的物体上下移动，在有效高度带内不应改变它所属的平面位置。高度带之外可不计入障碍。
- 当前障碍高度参数为离地0.10～1.90 m，可配置；不增加用户已经取消的身体余量或障碍膨胀。
- 状态：1=观测到障碍，2=遮挡/视野外/无效/证据不足。0的含义见第6节，必须统一后再接触觉输出。
- RGB、深度及矩阵保持相机原始左右关系。界面保留左上RGB、左下深度或分类图、右侧矩阵。

| 内容 | 当前状态 | 不能据此声称的能力 |

官方复现使用SpatialLM1.1-Qwen-0.5B，代码提交8913c44d84a450c53e9340b13317f8cf7144a738；Python3.11、PyTorch2.4.1+cu124、真实torch-scatter、spconv-cu120和FlashAttention，环境位于/opt/spatiallm-official。官方示例单次进度条推理计时约14.93秒，不含模型加载，不能作为实时延迟承诺。

照片失败案例：图一正放/倒地两把椅子在全类别SpatialLM结果中漏检；指定chair/dining_chair后仍出现远处异常框。新增RGB分割后在两把椅子位置得到置信度0.6245与0.3325的候选，后一项标记待确认。图二校正后有4个餐椅框、1个餐桌框，但仍有沙发等误检。以上仅是案例观察，没有检测准确率或三维定位精度结论。

## 3. 借鉴SpatialLM的具体部分

SpatialLM负责将点云解释成墙、门窗及带类别的物体有向框；输入要求Z向上且场景轴向对齐。官方支持指定家具类别检测。我们沿用官方模型、点云编码和推理接口，不在本阶段训练或微调模型。[官方仓库](https://github.com/manycore-research/SpatialLM)

本项目新增的内容是传感器标定、坐标转换、异步调度、预测验证、矩阵融合及RGB补检，而不是把SpatialLM输出直接缩小成9×6。官方有向框是物体包围范围，可能含空隙、遮挡部分和模型补全，不能把整个框自动当成已实测占用。

RGB补检采用实例分割提供的物体掩膜，再关联深度点，接口依据[Ultralytics官方分割文档](https://docs.ultralytics.com/tasks/segment/)。该路径与SpatialLM分别记录来源。

## 4. 拟采用的架构

```text
CS30 RGB / 深度 / 标定 / 时间戳       IMU（尚待接入）
                 ↓ 同步、深度语义确认、坐标校准
             有效深度点云 + 数据质量状态
                 ├─ 实时几何路径
                 │   地面/姿态 → 高度带 → 可见性 → 占用矩阵 → 界面/触觉
                 │
                 ├─ RGB实例分割补检
                 │   掩膜 → RGB/深度配准 → 实测点关联 → 类别/观测范围
                 │
                 └─ SpatialLM后台分析
                     关键帧点云 → 模型坐标对齐 → 官方模型 → 结构/物体候选
                                      ↓
                       来源、观测支持、坐标及时间有效性检查
                                      ↓
                       语义场景展示与受约束的辅助信息
```

实时几何路径持续独立运行。模型超时、无输出或类别判断错误不能阻塞采集，更不能把实测障碍清成空闲。SpatialLM主责是场景语义和结构解释，不负责改写CS30测得的距离。

## 5. 数据和坐标处理

### 5.1 必须先完成的传感器工作

读取并保存深度相机内参、畸变参数、RGB内参、RGB与深度外参、分辨率、深度单位和采集时间戳。优先使用SDK提供的点云或注册结果；相关接口、标定质量及时间戳含义须实际确认。

必须确认深度图表示光轴Z深度还是沿视线的径向距离。以下反投影公式仅适用于去畸变后的光轴Z深度：

Xc=(u-cx)·Zc/fx，Yc=(v-cy)·Zc/fy。

若SDK提供径向距离，则先按单位视线方向恢复三维，不能套同一公式。水平距离r=sqrt(x²+y²)，不使用相机斜距或r来替代前向坐标y。

RGB掩膜选点时，深度点经外参变换投到RGB坐标，并做可见性/遮挡检查和时间匹配。不能以分辨率缩放代替配准。

### 5.2 两套坐标分开

局部矩阵始终采用“头部前向”的地面坐标L。SpatialLM单独使用墙面轴向对齐的模型坐标M，并完整保存T_M←L及逆变换。模型输出返回L后才与当前视图比较。

这是必要的隔离：为了让SpatialLM输入对齐墙而旋转点云，不应同时旋转用户的左右/前后矩阵。官方PositiveShift产生的平移也必须恢复。

地面/重力有效时计算离地高度；镜头离地高度和安装倾角必须按当前实物填写。桌面测试约0.70 m、此前照片约1.75 m不能混用，旧硬件文档中的20°下倾也不能自动覆盖当前安装参数。

IMU接入前，以地面拟合和已知安装高度约束姿态，拟合失败显示降级状态。地面候选需要法线、脚下高度、覆盖范围及稳定性约束；上一帧结果仅作先验，不能无条件沿用。接入IMU后，还需标定相机与IMU的固定旋转和时间偏移。

### 5.3 单帧与多帧边界

第一阶段模型只分析单帧或明确静止采集的快照，不拼接移动头部的点云。IMU重力对齐并不能恢复相机平移、稳定全局航向或物体运动。

后续若要通过多视角减少遮挡，必须增加并验证RGB-D里程计/VIO或其他可观测位姿来源，才允许将多帧融合到同一坐标。不能只把“上一帧矩阵”加到“这一帧矩阵”。

## 6. 实时几何矩阵的规则

保留量程/无效值过滤、局部去噪、地面分离和高度带筛选。细体素可从5～10 cm、垂直层10～20 cm起试，但须依据CS30有效采样密度和性能选取，属于待验证参数。

1. 实测障碍点达到支持门槛时，对应40 cm格记1；薄椅腿不能仅因全局离群过滤被全部抹掉，去噪参数需有细障碍回归测试。
2. 有效射线只更新端点之前的可见空间；端点后方、被遮挡区域和视野外保持2。
3. 1优先于0。模型漏检、掩膜未识别、深度值为0，都不是空闲证据。
4. 固定长方形是输出坐标范围，不代表相机能看见其中每一格。近处两侧未知可能由视场决定，不能用模型填成0来使图案“铺满”。

**需要在本轮明确的0语义：**现有v0.19允许“看见地面且未检测到障碍”显示0，也保存高度覆盖诊断；这不足以证明整个人体高度可通过。建议保留调试的ground_seen，给正式输出增加free_coverage，只有高度带及格内横向子区域的可见覆盖达到经实测确定的门槛才显示0，否则2。此项会让0减少，不能默认为已经实现或直接继承旧绿色的含义。门槛及可用性需要审阅和现场实验。

时间稳定仅抑制抖动，并保存观测时间。相机移动且没有可靠位姿时不跨帧累积占用/空闲；不能把上一视角的障碍锁在当前格子。旧观测失效回到2，不自动回到0。台阶、坑洞和玻璃另列能力缺口，本版不声称覆盖。

## 7. 语义融合规则

| 证据 | 允许的作用 | 不允许的作用 |
|---|---|---|
| 有效CS30障碍点 | 更新实测障碍1 | 因模型说“地面”而被删除 |
| RGB掩膜＋配准实测深度 | 关联类别、聚合属于该物体的观测点 | 将二维矩形内全部深度都算作物体 |
| SpatialLM框＋同位置实测点 | 添加语义和方向，辅助解释实测障碍 | 因框较大把周围未观测格全部填1 |
| SpatialLM无点支撑的墙/框 | 只进入单独预测图层，标为推测 | 直接写入触觉实测矩阵 |
| RGB有物体但深度无效 | 显示二维候选/深度不足提示 | 虚构米制位置或把该区域清0 |
| 模型认为是门/窗 | 显示结构候选 | 自动判定门已打开、可通行或玻璃不存在 |

几何支持检查使用点到预测表面距离、支持点分布、与其他实例冲突和观测覆盖，而不只数框内点数。即使通过，也仅说明位置有几何证据，不证明类别、完整尺寸或门窗状态正确。

对于椅子，补检使用掩膜内有效深度及鲁棒离群处理；保留原始点和被剔除比例，避免单一中位数筛选抹掉同一物体较远的椅背/椅腿。旋转框可供展示，但矩阵优先投影实际支持点。未见部分仍未知，不按完整椅子先验自动补齐。第一版只在已验证类别上启用补检，其余物体仍由几何路径检障。

类别分数、几何支持、距离质量、时间有效性分别存储，不混成一个未经标定的“可信度”。当前YOLO的0.25检测门槛和0.5待确认分界只是实验设置，尤其倒地椅子0.33不能直接称作可靠检出概率。

## 8. 低频模型结果如何与运动中的相机共存

SpatialLM按最新关键帧异步分析，不排长队；进程常驻可减少重复加载，实际延迟仍须重测。实时几何使用独立采集/处理通道；模型GPU任务与RGB分割的资源竞争也计入端到端测试。

每次请求带frame_id、捕获时刻、标定版本、坐标变换及可选相机位姿；输出记录完成时刻与来源帧。**没有可靠相对位姿时，延迟返回结果只能显示在对应快照上，不得覆盖当前实时矩阵。**用户转头/移动、坐标校准变化或数据过期时，结果保持历史分析状态。

有经过验证的位姿后，才能转换到当前坐标；动态物体仍需重新观测，不能只按相机运动搬运旧框。超时、显存不足和通信失败退回几何路径，不重复播放旧结果。

## 9. 模块与部署

建议形成独立接口：

| 模块 | 输入→输出 |
|---|---|
| SensorAdapter | SDK数据→带时间戳/内参的FrameBundle |
| Registration | RGB、深度、外参→可关联像素/点及可见性 |
| GroundPose | 深度点、安装参数、可选IMU→地面/局部变换/质量 |
| GeometryGrid | 地面坐标点、可见性→grid、ground_seen、free_coverage |
| RGBInstance | RGB→掩膜、类别分数；配准深度→观测点集合 |
| SpatialLMService | 对齐点云、来源快照→原始布局和结构候选 |
| EvidenceFusion | 观测、候选、坐标与时间状态→语义信息/独立预测层 |
| OutputAdapter | 实测grid、质量状态→GUI、JSON、触觉协议 |

公共记录至少包含：frame_id、capture_timestamp、calibration_id、frame_name、transform、source、depth_quality、semantic_score、support_metrics、validity。触觉协议单独传未知状态，不能把2直接编码成与1等同的升起指令；具体设备表示方式待与执行端确认。

当前以Windows采集＋WSL GPU模型为验证平台；将旧SpatialLM桥接迁移到已经跑通的官方依赖环境，保留原始输出及可复现种子。轻量模块与GUI解耦。

Radxa ZERO 3W暂承担目标采集/轻量几何/通信角色，实际性能未验证；本方案不承诺在该板上运行CUDA SpatialLM。手机负责显示/交互或后续经验证的计算任务，不把“已有手机”视为模型已能运行。第一阶段不增加云依赖。实际移动端部署及模型/依赖许可需在选定发布方式后分别核对，不能把整个依赖链按统一宽松许可处理。

## 10. 实施与验收顺序

### 第一步：让测量与坐标可信

保存连续RGB-D、时间戳、标定和失败状态；完成SDK深度语义核对、RGB深度配准、地面/坐标验证。摆放静态靶物，测试左右、前后、镜头高度和倾角变化。目标是解释映射误差来源，而不是先换更大的模型。

### 第二步：接通实时几何与掩膜关联

以CS30实测深度代替当前单目估计；用正放、倒地、遮挡椅子回归，同时保留无类别几何障碍检测。配准未通过时禁用掩膜的三维融合，仅显示二维识别。

### 第三步：统一SpatialLM服务和证据融合

先静止快照，再验证延迟/过期处理；模型输出只补语义和预测层。验证不含模型、纯SpatialLM、仅掩膜补检、融合四种方案，不能只展示最好的截图。

### 第四步：决定是否增加运动估计与多帧重建

只有单帧覆盖不足且确实影响功能时，再增加RGB-D里程计/VIO；用同步位姿和动态物体测试验收后开放移动中的多帧融合。先不把这项当成已经具备的能力。

### 建议验收项目（目标值须依据基线确定）

- 几何：水平x/y误差、离地高度误差、格子混淆矩阵；物体上下移动时的XY漂移。专门测试格边界，避免用单次越界计数掩盖误差。
- 识别：实例级漏检/误检，分正放与倒地姿态；人工标注全图，不只看两张已知案例。检测、定位和占格精度分别统计。
- 观察状态：视野外/被遮挡正确保持2；不可通行格被错误显示0的比例；全未知比例也报告，防止靠全部置2获得虚假的保守效果。
- 稳定性：固定场景矩阵翻转率、出现/消失响应；转头/行走时历史结果是否错位。
- 系统：按采集时刻计算P50/P95端到端延迟、丢帧/断流/重连，模型并发时的资源占用及持续运行。
- 失败场景：黑色/反光表面、玻璃、细椅腿、桌底空隙、人员移动、地面被挡。没有深度真值的照片试验只用于识别观察，不能支撑厘米级精度结论。
